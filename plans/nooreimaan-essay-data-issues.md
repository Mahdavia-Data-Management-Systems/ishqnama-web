# Noor e Imaan essays: data issues (tech debt)

**Status: catalogued 2026-10-16, not fixed.** Found by reading all 22 essay files in
`backend/src/Ishqnama.Application/Articles/NoorEImaan/`. Nothing here breaks rendering; each item
is a run tagged with the wrong `kind` (so it gets the wrong font and direction), a stray fragment
left by the converter, or a typo carried over from the source.

The files are generated by `frontend/scripts/build_nooreimaan_articles.py` (`npm run
articles:build`) from the gitignored `.ishqnama/articles/31.html`, so most fixes belong in the
converter (or the source HTML), not in hand edits to the JSON, which the next build would undo.

Locations are `<slug> | block <index> <type> [row.side[line]] run <index>`, zero-based, as the
blocks sit in the file today.

## 1. Whitespace-only runs

A run whose text is a single space, wedged between two runs. Harmless on screen, but noise for
any consumer and a sign the converter splits on formatting it should merge.

- `dua-after-farz-namaz` | block 7 p run 1 (arabic); block 8 pair row0.rendering[0] run 1 (arabic)
- `harf-e-zaid` | block 2 p run 7 (arabic)
- `hazf` | block 17 p run 8 (arabic)
- `is-the-quran-connected` | block 15 p run 1 (arabic); block 19 p run 2 (arabic)
- `istisna-munqati` | block 9 p run 7 (arabic)
- `mahdi-and-isa` | block 31 pair row0.quote[0] run 1 (urdu)
- `raising-hands-in-dua` | block 4 p run 2 (arabic)
- `tark-e-dunya` | block 13 pair row0.quote[0] run 1 (urdu)
- `eighteen-ayaat` | h2 blocks 33, 36, 41, 53, 57, 62, 65, 68, 74, 78 (urdu spaces between the
  heading's pieces)

**Fix:** in the converter, fold a whitespace-only run into its neighbour.

## 2. Words split across runs

One word or one letter torn off into a run of another kind.

- `dua-after-farz-namaz` | block 8 pair row0.rendering[0] runs 1–3: `" "` (arabic), `"ا"` (urdu),
  `"للهم انت السلام…"` (arabic). The alif of اللهم sits alone in an urdu run.
- `istisna-munqati` | block 21 p runs 0–2: the opening `وَمِنهُمْ` of the quotation from Tafsir
  Mahaimi is split into `"و"` (arabic) and a lone fatha `"َ"` (urdu), so the harakah renders
  detached.
- `istisna-munqati` | block 10 p runs 1–2 (the Ibn Atiyya quotation): the arabic run ends
  `إلَّا قَوم` and the next urdu run starts `یونس`, splitting قوم يونس.
- `ghazwa-e-hind` | block 55 p run 0: the urdu run ends `چوتھی صفت ق` and the next quran run is
  `قَـٰتَلُوا وَقُتِلُوا`. The stray `ق` is the start of the underlined word, duplicated.
- `repetition-in-the-quran` | block 32 p run 8: the urdu run starts `ے بعد`. It belongs to the
  word کے, whose `ک` was swallowed into the preceding quran run's boundary.
- `irab-in-the-quran` | block 7 p run 4: `"ہ"` tagged arabic. It quotes the Arabic letter ه but
  uses the Urdu heh (U+06C1).

**Fix:** converter: merge a run of one or two characters into its neighbour when they share a
word (no space between them); check the source HTML for the duplicated underline letters.

## 3. Urdu tagged as Arabic in `eighteen-ayaat` headings

Most h2 headings carry Urdu text in an `arabic` run, so they get the naskh font instead of
Nastaleeq: blocks 1, 33, 36, 41, 45, 53, 57, 62, 65, 68, 71, 74, 78, 85 (e.g. block 1 run 3
`سب سے پہلی آیت سورۂ بقر جزو ۱ رکوع ۵۱ میں ہے`). Headings 1–5 and 18 also wrap the number in
`(`, `۱` (arabic), `)` as three runs; the others write `۶۔` inside the arabic run. The heading
format differs across the 18 sections.

**Fix:** retag as urdu and give the 18 headings one shape (one urdu run, e.g. `(۶) چھٹی آیت سورۂ
انعام جزء ۷`).

## 4. Arabic or Persian inside urdu runs (and the reverse)

Arabic passages that the source did not mark, so they render in Nastaleeq: mostly in `hazf`
(the worked examples), `harf-e-zaid`, `istisna-munqati` and `irab-in-the-quran`, where an Arabic
phrase runs on inside an urdu run before or after a correctly tagged one. `suhbat-e-sadiqeen`
block 13 quotes Shaykh Abdul Haqq's Persian (`کسے بیاید کہ مساوی باشد…`) inside an urdu run.

**Fix:** needs a reader, not a script: go through these four essays with the source open.

## 5. Persian couplets with the hemistich break lost

The two hemistichs run together with no space or separator:

- `tark-e-dunya` | block 52 p run 0: `ہم خدا خواهی و ہم دنیائے دوںایں خیالست…` (`دوں` + `ایں`)
- `suhbat-e-sadiqeen` | block 19 p run 1: `سگ اصحاب کہف روزے چندپئے نیکاں گرفت…` (`چند` + `پئے`),
  and the couplet's two lines run on without a break

**Fix:** render couplets as a `pair`-style verse block (one line per hemistich), as
`repetition-in-the-quran` already does for the Arabic elegies.

## 6. Mixed Quran scripts

Some `quran` runs use the Uthmani script of the reader (`ٱ`, `ـٰ`, `ىٕ`; e.g. `amanat`,
`eighteen-ayaat`, `tark-e-dunya`), others plain Imla'i spelling (`harf-e-zaid`, `hazf`,
`naskh`, `irab-in-the-quran`). Both render, but the same verse looks different from essay to
essay.

**Fix:** decide one script; the Uthmani text could be taken from the reader's own verse data
by reference.

## 7. Typos in the text

Carried over from the source; they need the book checked before changing:

- `dua-after-farz-namaz` | block 19: `مردہ کی پہاڑی` should read `مروہ کی پہاڑی` (Marwa; the
  mnemonic letter is م).
- `irab-in-the-quran` | block 4 run 3: `وَهُمْ مُوتُونَ الزَّكاةَ` should be `مُؤْتُونَ`.
- `irab-in-the-quran` | block 3 run 8: `نہ تو کسی حرام کو حلال کرتا ہے اور نہ کسی حرام کو حلال
  کرتا ہے` should read `…اور نہ کسی حلال کو حرام کرتا ہے` (it renders لا يحل حراما ولا يحرم حلالا).
- `tark-e-dunya` | block 31: `ابراہیمؐ` carries the Prophet's honorific `ؐ`; Ibrahim takes `ؑ`.
- `amanat` | blocks 9, 12: `ظلوم اور جھول` for `ظلوم اور جہول` (the verse's جَهُولًا).
